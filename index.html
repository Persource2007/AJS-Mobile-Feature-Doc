Product Handbook

AJS Mobile

The field engineer's complete on-site working tool — for maintenance, inspection and compliance visits across UK social-housing and commercial properties. Delivers the day's work, guides a controlled sequence of safety and access checks, records everything done on site, and closes the job off — fully offline, syncing in the background.

What an RLO user sees differently
  • No Property tab, no Certificates tab, no asset handling, no van stock, no task filters, and no add buttons.
  • Appointment-scheduling closure: Their task closes through an appointment-scheduling screen rather than a technical review and sign-off.
  • Limited side menu: The side menu shows only All Tasks and, where permitted, Timesheets.
What the three account switches change
  • Price visibility off: hides every monetary value across the application.
  • Location tracking off: stops background position sharing (arrival checks still work).
  • Timesheet submission off: removes the Timesheets entry from the menu and dashboard entirely.

06 — Features

Forty-one features

Search or filter by area to find how a specific capability behaves. Tap a card to see the full picture — how it works, what's required, and what happens when something goes wrong.

41 features
FEA-01

Sign In

All users

Establishes the user's identity and loads their working data onto the device.

How it works. Before signing in, the application requests location and notification permissions and asks to allow exact scheduled alarms (for automatic check-out). It checks a connection is available and that device location is switched on. On success the account's price, location and timesheet switches are applied and the full initial data load begins with a visible progress percentage — tasks, master data, van stock, health and safety questions, certificates and the phrasebook.

Conditions. Requires a connection and device location switched on. Notification permission may be declined; alarm permission may be skipped, which disables automatic check-out only.

If something goes wrong. No connection shows a message and nothing is attempted. Rejected credentials show the back office's message. If part of the data load fails, the user still reaches the dashboard and the failed portions retry automatically next launch.

FEA-02FEA-04FEA-38

FEA-02

Additional Verification (2FA / MFA)

Accounts with 2FA/MFA

Confirms identity with a second factor before granting access.

How it works. For two-factor verification, a code is sent and can be resent after a countdown. For multi-factor verification, the code comes from the user's authenticator app and no resend is offered. Entering the full code submits automatically.

Conditions. The back gesture does not return to sign-in — verification must be completed or the app closed.

If something goes wrong. Incomplete or blank codes prompt the user; an incorrect code shows the back office's message; no connection shows a message.

FEA-03

Multi-Factor Setup

New MFA users

Enrols a new user's authenticator application.

How it works. Offered automatically after a first password is set on an account requiring MFA. The screen shows a scannable code and a copyable key; entering the generated code confirms enrolment and returns the user to sign in.

Conditions. Only reached from the password-set flow, not from within the signed-in application.

If something goes wrong. Invalid or blank codes are rejected with a message.

FEA-04

Forgot Password

All users

Lets a user who cannot sign in request a recovery link.

How it works. The user enters their username or email; the back office issues a recovery message and the application confirms it has been sent.

Conditions. Requires a connection. The identifier must not be blank and may only contain letters, digits, and @ . _ -.

If something goes wrong. Field errors for invalid input; a message for no connection or a back-office rejection.

FEA-05

Set or Reset Password by Emailed Link

All users

Lets a new user create their first password, or a locked-out user set a new one.

How it works. Opening the link from email opens the app directly on this screen. Wording and button text adapt to first-time creation vs. reset. Where MFA is required, the user is taken to MFA setup; otherwise back to sign in.

Conditions. Requires a connection. The link is single-purpose and time-limited by the back office. New password must be at least six characters and match its confirmation.

If something goes wrong. An expired or invalid link is rejected with the back office's message; field errors for blank, short or mismatched passwords.

All users

Lets a signed-in user change their password.

How it works. From the profile screen. Requires the current password plus a new password and confirmation. A confirmation is shown on success.

Conditions. Requires a connection.

If something goes wrong. Field errors; the back office's message when the current password is wrong.

FEA-07

Sign Out

All users

Ends the session and clears the device.

How it works. First checks whether recorded work is still waiting to be uploaded. Depending on what's outstanding, it blocks sign-out, warns that unsubmitted certificates will be lost, or simply confirms. On confirmation the session ends and all locally stored data, settings and temporary files are cleared.

Conditions. Requires a connection. See BR-175.

If something goes wrong. No connection produces a banner and a message; sign-out does not occur.

FEA-08

Check In and Check Out

All users

Records daily attendance and unlocks the ability to record work.

How it works. Tapping the dashboard tile requests location permission, confirms the action, and records it with the back office. Checking in starts background location sharing (where the account permits it) and periodic background refresh; checking out stops both. The tile changes colour and caption, and a green banner confirms the change.

Conditions. Cannot be done offline. Location permission required before the confirmation dialog appears. See BR-002, BR-003, BR-004.

If something goes wrong. No connection produces a banner and the state stays unchanged. Declining location permission prevents the confirmation dialog from appearing.

FEA-09

Dashboard Overview

All users

Gives attendance control and an at-a-glance view of outstanding work.

How it works. Counters read from data already on the device, so they work offline. Each tile — All Tasks, Today, Reactive, Overdue, Van Stock, Timesheets — jumps to the matching pre-filtered list.

Conditions. For RLO users the technical tiles are hidden and the second tile becomes Timesheets. Hidden entirely when the timesheet switch is off. Zero counters are hidden. See BR-075, BR-076.

FEA-10

Task List, Search and Filters

All users

Lets the user find and open the task they intend to work on.

How it works. Served from data already on the device; pull-to-refresh fetches an update. Date, task type and location filters combine and persist between sessions. Expanding a card reveals its summary and action buttons — only one at a time.

Conditions. Filters hidden for RLO users. See BR-070–BR-075. The location filter's ordering is Needs verification — see BR-190.

If something goes wrong. Pull-to-refresh without a connection shows a no-connection banner. Empty results show a "no tasks" or "no matches" state.

FEA-11

Task Status Progression

All users

Moves a task through its lifecycle, recording where and when each step happened.

How it works. Each step presents its own confirmation with an animation. The device position is captured at the moment of change and recorded with the back office, or queued if offline. Arrival triggers the location check where applicable, then property warnings.

Conditions. See BR-001, BR-020–BR-022, BR-030–BR-032.

If something goes wrong. Checked-out users see a check-in prompt instead. A failed location check offers retry. A back-office rejection shows a message and the status stays unchanged.

FEA-12

Property Warnings and Resident Alerts

All users

Ensures the user sees recorded hazards before entering a property.

How it works. Shown automatically on Arrival. Warnings appear first as a list that cannot be dismissed without acknowledgement; acknowledging shows resident alerts if any exist. Not shown again once acknowledged for that task.

FEA-13

Property Access and No-Access Closure

All users

Records whether the user could get into the property, and closes the task properly if not.

How it works. Yes moves to health & safety (or straight to task start for RLO). No reveals an evidence form: a reason, a written explanation, and photographic evidence. Some reasons reveal a reschedule question, and either a self-assigned date/time or routing to the office.

Conditions. See BR-040–BR-043, BR-001.

If something goes wrong. Missing reason, comment, or fewer than two media items block submission with field errors and a shake animation.

FEA-14

Health and Safety Checklist

Engineers only

Confirms the site is safe to work in before the task can start.

How it works. Every question has a defined expected answer. All matching moves to the asbestos review; any deviation shows the failure screen, where declaring work cannot continue closes the task as H&S Failed, and declaring it can requires the supervisor's advice in writing first.

Conditions. RLO users bypass this step entirely. See BR-050–BR-052.

FEA-15

Asbestos Review

Engineers only

Confirms the site has been checked against the asbestos register.

How it works. No or Not Applicable clears the pre-start checks and returns to the task screen ready to start. Yes shows a warning and, on confirmation, closes the task as Asbestos Failed.

Conditions. See BR-060–BR-062. The register link is only offered when the task carries one.

Contacting People and Navigating to Site

All users

Lets the user reach the property and the people involved.

All users

Lets the user record a written note against the task.

Task Media Capture

All users

Attaches photographic and video evidence to the task.

Property Browsing

Engineers only

Gives the user the wider context of the property they are visiting.

How it works. Three sub-areas — Tasks, Assets, Certificates — show what's already on the device and refresh from the back office on pull-to-refresh: the property's other work, its full asset register, and its previously issued certificates.

FEA-20

Property Asset Register and Linking

Engineers only

Lets the user find existing equipment at the property and attach it to the current task.

How it works. Long-pressing enters a selection mode with a header count and a link control. Linking creates task assets in the Pending outcome and clears the selection.

FEA-21

Add Asset

Engineers only

Records a new piece of equipment discovered at the property.

How it works. Type, make and model come from device reference data; make can be typed if unlisted. Most models are tied to a specific make, but some are generic and offered regardless of which make is chosen. Saving stores the asset locally and queues it for upload with any media, documents and the task link.

Conditions. Requires an asset type and a make. Installation date, warranty dates and expiry date can only be set to today or later — see BR-089. Documents follow the size and type limits in BR-180.

If something goes wrong. Field errors on mandatory fields; oversized or unsupported documents are rejected.

Record Asset Outcome

Engineers only

Records the result of inspecting a piece of equipment.

How it works. Choosing Pass, Fail, Limitation or Retire reveals the relevant supplementary controls. From the list, assets can also be multi-selected and marked Pass together, or deleted together.

Conditions. Fail and Retire require a comment and at least one photograph — see BR-085. See also BR-086, BR-087.

Asset History and Documents

Engineers only

Shows what has previously happened to an asset and what paperwork exists for it.

How it works. History lists previous recorded actions, refreshed on pull-to-refresh. Resources lists attached documents grouped by date; opening one downloads it and hands it to the device to display.

Conditions. Refreshing and opening a not-yet-downloaded document require a connection.

FEA-24

SOR Management

All users, incl. RLO

Records what work was carried out, in priced and coded form.

How it works. The SOR selector searches the master list for the task's job. Where the item consumes materials, a stock selector appears and availability is checked. A single work item can bring a whole package of certificates onto the task at once. When editing, only quantity, comment and media can change — not the item itself.

Conditions. See BR-090–BR-096, BR-102.

If something goes wrong. Field errors for the item and quantity; messages for missing or insufficient stock; a hard block where an enforced threshold would be breached.

FEA-25

Spend Threshold Check and Approval

Tasks with a threshold

Prevents a task's value exceeding its authorised limit without supervisor approval.

How it works. The value of the task's work items is totalled and compared against the threshold. Over the limit on an advisory task, an approval comment is requested and stored; over the limit on an enforced task, the item cannot be added at all.

Conditions. See BR-095, BR-100–BR-102.

FEA-26

Certificate Completion

Engineers only

09 — Offline & Sync

Nothing depends on a signal

The application assumes the engineer will regularly lose connectivity — basements, plant rooms, rural properties, lifts — and that losing it must never cost them work.

The offline principle. Everything the user records is written to the device first. The back office is updated afterwards, in the background. The user is never asked to wait for an upload, and never has to retry a recording action because a connection was missing. A short list of features are refused clearly instead — they're meaningless without a live answer from the back office.
Fully available offline
  • Dashboard, task list (search & filters), completed tasks
  • Task status changes — on route, arrived, start
  • Property access, no-access closure, H&S, asbestos review
  • Adding, editing and deleting assets, SORs, media, comments
  • Completing, submitting and clearing certificates
  • Full task closure — signatures, observations, non-completion
  • RLO appointment outcome; threshold approval comment
Requires a connection
  • Signing in, verification codes, all password operations, sign-out
  • Checking in and checking out
  • Refreshing lists — task list, property data, asset history
  • Downloading a certificate's structure the first time
  • Previewing or opening a produced certificate document
  • The whole of Timesheets — no data is held on the device
  • Editing the profile; manual synchronisation, by definition

Once a certificate has been opened while connected, its structure stays on the device — it can then be completed and submitted entirely offline. One never opened while connected cannot be started offline.

Locally stored data is cleared in exactly two circumstances: the user signs out deliberately, or the session cannot be renewed.
